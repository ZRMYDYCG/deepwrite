# 子智能体抽卡模式设计

> 状态：已实现，未提交（2026-10-02）。自动测试与界面检查已通过，真实模型的抽卡流程还没有试跑。本文是实现依据；后续改动如需偏离，先改本文再改代码。

## 1 背景与目标

润色、起标题、写片段这类任务，同一个要求多跑几次，结果质量差别很大。抽卡模式让一个子智能体收到任务后在后台独立运行多次，得到多份候选，再由用户或评估助手选出一份，只把这一份交回主智能体。

一期目标：

- 团队成员多一个“抽卡模式”开关。只有运行模式为纯净·只读或纯净·无工具的成员可以打开。常规成员有写入工具，抽 N 次就会写 N 遍，所以不允许。
- 抽卡次数可配，2–10 次，默认 3 次。
- 选择方式分手动和自动。手动：全部候选跑完后，在 ask_user_question 的位置弹出选择卡。自动：由评估助手按可编辑的规则选择，它只有一个选择工具，并且必须以调用这个工具结束。
- 主智能体的调用方式不变，拿到的结果只有被选中的那一份。

一期不做：再抽一轮、手动模式下先让评估助手推荐、两份候选的差异高亮、按模型限流。

## 2 已确认的决定

| # | 决定 | 说明 |
| --- | --- | --- |
| 1 | 开关按成员配置 | 挂在成员编辑页“运行模式”下方。不同成员的次数和评估规则差别很大，所以不做团队级开关 |
| 2 | 同一任务的 N 份总是同时跑 | 团队没开并行也一样。整次 `spawn_subagent` 调用同时运行的子运行（普通任务、抽卡、评估助手）最多 10 个，多出的排队 |
| 3 | 手动“都不采用”按未完成交回 | 任务以失败状态交回主智能体，附上用户附言，由主智能体决定怎么改任务再派。依赖它的任务跳过。“再抽一轮”放二期 |
| 4 | 评估助手必须调用选择工具 | 任务消息开头和结尾都强调必须调用 `select_candidate`。没调用就结束时追问一次；仍未调用或评估出错，改为手动选择 |
| 5 | 评估助手的模型可单独配置 | 默认继承主智能体的模型，与子智能体“继承”的含义一致；也可以单独选模型、思考等级和温度 |

以下默认值实现时照此处理，可以再调整：

- 成员改回常规模式时自动关闭抽卡，但保留次数、选择方式和评估设置。运行时也只对纯净成员生效。
- 评估规则没改过就不存，直接用内置默认，这样以后改进默认提示词，老配置也能用上。“恢复默认”就是清空自定义规则。
- 每份候选都是全新的子运行。系统提示词、任务、前置交接和素材上下文完全相同，候选之间互相看不到，也不告诉它是第几份。
- 资料库管理成员恒为常规模式，不参与抽卡。扩展域的子任务（`workspaceAccess: "none"`）不读这个字段。

## 3 配置

### 3.1 数据结构

成员定义（`packages/contracts/src/agent-team.ts`）新增可选字段 `draw`。运行模式、模型模式和抽卡的 schema 放在 `subagent-settings.ts`，由 `agent-team.ts` 再导出：

```ts
draw?: {
  enabled: boolean;
  count: number;                 // 2–10，默认 3
  selection: "manual" | "auto";  // 默认 manual
  evaluator: {
    prompt?: string;             // 不填即用 DEFAULT_SUBAGENT_DRAW_EVALUATOR_PROMPT
    modelMode: "inherit" | "custom";
    modelId?: string;
    thinkingLevel?: ThinkingLevel;
    temperature?: number;
  };
}
```

- 自定义模型的校验规则与成员一致：选“单独配置”必须选模型和思考等级，思考关闭时必须选温度。两处共用一个校验函数。
- 缺省 `draw` 等于关闭。旧客户端读到会丢掉这个字段，退回普通运行，与纯净模式的兼容方式一致。
- `DEFAULT_SUBAGENT_DRAW_EVALUATOR_PROMPT` 放在 contracts，并从 `renderer.ts` 导出，设置页显示和运行时使用同一份默认文本。

### 3.2 Main 解析评估模型

`agent-team-run-mode.ts` 解析成员自定义模型时，同时解析已启用抽卡、选择方式为自动且单独配置了模型的评估助手，放进同一个 `subagentRuntimeConfigs`（按模型配置 id 索引）。`session/commands.ts` 中“自定义模型必须有运行配置”的校验同样覆盖评估模型。

### 3.3 设置页

成员编辑页“运行设置”在运行模式下方新增 `SubagentDrawField`：

- 抽卡开关（`AgentTeamSwitch`）。常规模式下不可打开，并显示“仅纯净模式可用”。
- 打开后显示：抽卡次数（`PopupSelect`，2–10 次）和选择方式（`AgentTeamSegmented`：手动 / 自动）。
- 选“自动”时再显示评估助手：模型（复用 `SubagentModelField`）和评估规则文本框（显示默认文本，提供“恢复默认”）。
- 开关下方的说明文字：每次委派后台生成多份结果，只把选中的一份交回主智能体，消耗约为 N 倍（自动模式另加一次评估）。
- 成员卡片的模式徽标后加“抽卡×N”。
- 草稿签名 `agentTeamDraftSignature` 必须包含 `draw`，否则改了抽卡设置也不会提示未保存。

## 4 运行流程

### 4.1 主智能体侧

`spawn_subagent` 的参数不变。成员列表中抽卡成员名后追加标记：“［抽卡×N：系统会自动生成 N 份结果并择优，只返回选中的一份］”，主智能体就不会再要求该成员“多给几个版本”。

### 4.2 抽卡

调度器照常按依赖和并行名额启动任务。任务属于抽卡成员时，由 `subagent-draw.ts` 接管：

1. 同时启动 N 个子运行，每个都通过 `runSubagentTask` 运行。进度事件带 `draw: { role: "candidate", index, count }`。
2. 整次调用共用一个子运行限流器（`concurrency-limiter.ts`，上限 10）。普通任务、每份候选、评估助手各占一个名额。抽卡任务本身只占调度器名额，不占限流器名额，所以不会互相等死。
3. 全部候选结束后统计成功份数：
   - 0 份：任务失败，摘要写明“抽卡 N 份全部失败”并附第一份的错误。
   - 1 份：直接采用，摘要注明其余几份失败。
   - 2 份及以上：进入选择。

### 4.3 手动选择

- 通过运行内核的 `requestUserInput` 发出 `source: "subagent_draw"` 的请求。请求带一个说明性问题（id `draw`）和 `draw` 字段：成员名、任务 key、任务原文和全部成功候选（id `c1`…`c10`、序号、子运行 id、全文）。
- 用户的回答复用 `AgentUserInputAnswer`：`selectedOptionIds` 为一个候选 id 或保留值 `reject`（都不采用），`text` 为可选附言。broker 在请求带 `draw` 时按候选 id 校验。
- 现在的 broker 每个运行只允许一个待回答的请求。改为由运行内核按先后顺序排队（复用容量为 1 的 `concurrency-limiter`）：前一个请求结束后才发出下一个，排队期间同样暂停空闲超时。这样并行时多组候选依次弹出，也顺带避免并行常规成员的跨阶段确认撞车。
- 选择期间其他子任务照常运行，依赖该任务的任务继续等待。等待选择不计入子智能体超时。

### 4.4 自动选择（评估助手）

`subagent-draw-evaluator.ts` 新建一个独立的子运行，进度事件带 `draw: { role: "evaluator", count }`，名称为“评估助手”：

- 系统提示词由两部分组成：评估规则（用户可改）和不可编辑的【抽卡评估运行边界】，后者规定只依据任务和候选判断、必须调用一次 `select_candidate`、不改写候选。
- 任务消息的开头先强调“读完后必须调用 select_candidate 提交选择，这是唯一有效的输出”，接着是原任务和编号候选，结尾再提醒一次。
- 唯一的工具是 `select_candidate({ candidate: 1–N, reason: string })`。工具结果设 `terminate: true`，运行在调用后结束。重复调用只记第一次。
- 运行结束而没有调用工具时，用 `followUp` 追问一次。仍未调用，或评估出错、超时，就发事件说明原因，改为 4.3 的手动选择。
- 候选总长度按评估模型的上下文预算截断：总字数取 100,000 和上下文窗口一半中的较小值，按份数平均分，被截断的候选注明“已截断”。
- 评估助手不读作品、不加载素材上下文，也不继承主对话。

### 4.5 交回主智能体

只有选中的那一份进入主智能体的上下文和 `depends_on` 下游的交接，前面附一行说明：

```
【抽卡结果】共 5 份（成功 5 份），评估助手选择第 3 份。理由：……

<候选 3 原文>
```

手动选择时写“用户选择第 k 份”，有附言就附上“用户附言：……”。都不采用时，任务以 `error` 交回：“用户没有采用这次抽卡的 N 份候选。用户附言：……”。

### 4.6 中止

停止主运行会中止所有候选、评估助手和待选请求，任务记为中止。

## 5 协议与事件

| 位置 | 改动 |
| --- | --- |
| `contracts/agent-team.ts` | `SubagentDrawSettingsSchema`、次数与长度常量、默认评估提示词 |
| `contracts/session/subagent.ts` | `SubagentDrawRefSchema`；started / activity / completed 载荷可带 `draw`；计划任务可带 `drawCount`；新增 `subagent.draw_updated` 载荷 |
| `contracts/session/user-input.ts` | `source` 新增 `subagent_draw`；请求载荷可带 `draw`（2–10 份候选），且 `source` 与 `draw` 必须同时出现；保留选项 id `reject` |
| `contracts/session/envelopes.ts` | 注册 `subagent.draw_updated` |

`subagent.draw_updated` 的 `phase`：

| phase | 含义 |
| --- | --- |
| `selecting` | 候选已跑完，等待用户选择（含排队） |
| `evaluating` | 评估助手运行中 |
| `selected` | 已选定，带 `selectedBy`（`user` / `evaluator` / `only-success`）、`selectedIndex`、`selectedSubagentRunId`、`reason` 或 `note` |
| `rejected` | 用户都不采用，带 `note` |
| `failed` | 全部候选失败，或任务被中止 |

评估失败转手动时先发一条带 `reason` 的 `selecting`，界面据此说明“评估助手未完成选择，已改为手动”。

事件路径与 `subagent.planned` 一致：adapter `subagent-events.ts` → `runtime-types.ts` → Utility `agent-event-envelope.ts` → Main `index.ts` 转发 → Renderer `event-kinds.ts` / `events.ts`。

## 6 对话界面

### 6.1 任务卡片

- `AgentSubagentRun` 新增 `draw` 和 `drawCount`（排队中的抽卡任务显示“抽卡×N”）。`subagentDrawGroups.ts` 把同一任务的候选和评估助手归成一组，`SubagentRunList` 用 `SubagentDrawGroup` 显示为一张抽卡卡片：标题行显示“抽卡中 2/3”“等待选择”“已采用候选 2”等状态，展开后是任务、选择说明和逐份的子卡片。子卡片复用从列表中拆出的 `SubagentRunCard`，被采用的一份标“已采用”。批次概况把一个抽卡任务计为一个子任务。
- 抽卡的整体状态记在 `ChatMessage.subagentDraws`，按 `parentToolCallId` 加批次序号索引，随对话记录持久化；`parse-message` 和 `clone` 同步支持。
- `subagentRunDetailId` 对候选加上序号，避免同一任务的多个子运行用同一个展开状态 id。

### 6.2 选择卡

请求的 `source` 为 `subagent_draw` 时，`AgentConversation` 用 `SubagentDrawPickerCard` 替换输入框（与 ask_user_question 同一位置）。对话栏较窄，候选又长，所以不用竖排选项：

- 标题“选一份交给主智能体”，副标题为成员名、任务 key、候选份数，以及“还有 N 组待选”（由 `subagentDraws` 中处于 `selecting` 的其他任务数得出）。
- 一排横向编号签，签上带字数，可以点击或按数字键切换。
- 一个预览区只显示当前候选，按 Markdown 渲染，可以滚动。
- 底部是附言输入框、“都不采用”按钮，以及中性深色主按钮“采用候选 k”。
- 右上角“展开对比”打开 `SubagentDrawCompareDialog`（Teleport 弹窗）：左右两栏各自切换候选并排阅读，每栏都有“采用此份”。窄窗口下改为上下两栏。
- 原任务折叠在副标题下方，点开可看。

## 8 测试与验证

- contracts：`draw` 的默认值、次数范围、评估自定义模型校验；`subagent_draw` 请求的 `source` 与 `draw` 必须同时出现。
- adapter：
  - N 份同时启动，不受团队并行开关影响，限流器上限生效。
  - 部分失败、全部失败、只剩一份成功。
  - 手动选择、都不采用（带附言）、中止。
  - 评估助手正常选择，未调用工具时追问一次，追问后仍不调用就转手动。
  - 只把选中的结果交给主智能体和下游任务。
  - 用户输入请求排队。
  - 常规成员即使带 `draw` 也不抽卡。
- broker：候选 id 和 `reject` 的校验。
- Renderer：设置字段的禁用与联动、草稿签名、抽卡卡片的合并展示、选择卡的切换与提交、事件处理与持久化往返。
- 运行验证：用临时 vite harness 在 Browser 窗格里检查设置区和选择卡，包括浅色、深色、窄窗口和较大字号。Faux 模型触发不了子智能体，真实抽卡流程需要用户用真实模型试一次。
